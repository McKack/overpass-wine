## Build changes

| Change | Why | Verified |
|---|---|---|
| Build SDL 2.30.12 from source instead of Homebrew's `sdl2` | Homebrew's `sdl2` is `sdl2-compat` (SDL3 underneath). With it, `winedevice.exe` aborts when loading `winebus.sys`: `NSWindow should only be instantiated on the main thread!`. Setting winebus `Enable SDL`=0 stops the crash, which confirms SDL as the cause. CrossOver 26 ships SDL 2.30.12. | Crash reproduced locally with build a8d4038. With CrossOver's SDL 2.30.12 in its place, a prefix boots on an M4 Mac and winebus.sys starts its SDL loop. On the CI runner (no desktop session) the first build with our SDL hung in `wineboot --init`; the smoke test now has time limits and hid traces to show where |
| ccache for clang (unix side), mingw (PE side) and the SDL build; CI keeps the cache between runs | A full build takes 80–112 min on the Intel runner; a small patch should only recompile what changed | Pending: first cached run fills the cache, the second shows the gain |
| GStreamer 1.28.8 (`build-gstreamer.sh`, `bundle-gstreamer.sh`), `--with-gstreamer` | Game video through Media Foundation and DirectShow was missing entirely. Built from GStreamer's own sources with every dependency from its subprojects, only the plugins games need: what CrossOver 26 ships (MP4, AVI, ASF, WAV; H.264, HEVC, AAC and MP3 through Apple's VideoToolbox and AudioToolbox) plus Matroska/WebM with VP8/VP9 (libvpx 1.17.0), Opus and Vorbis, which CrossOver lacks and UE4/UE5 cutscenes use. No GPL or libav parts. OverPass sets `GST_PLUGIN_SYSTEM_PATH`, `GST_PLUGIN_SCANNER` and `GST_REGISTRY`. Licence texts in `licenses/` | Local build (11.0-5): `mfplay` test opens and decodes MP4 (H.264/AAC), WebM (VP8/Vorbis, VP9), WMV and WMA; `xwma` test decodes xWMA through XAudio2. Libraries are bundled under their install names and build-folder rpaths are removed and checked for (winegstreamer.so had one and loaded a second GStreamer) |
| libinotify 20240724 (MIT), `--with-inotify` | CrossOver ships it: wineserver needs it for folder change notifications (`FindFirstChangeNotification`, `ReadDirectoryChangesW`), which launchers and games wait on | Local build (11.0-5): `notify` test passes FindFirstChangeNotification and ReadDirectoryChangesW (both failed on 11.0-2) |
| Libraries built from source (`build-deps.sh`: FreeType, GnuTLS with GMP and Nettle, SDL 2, libinotify, Vulkan loader, MoltenVK) | Homebrew no longer has Intel packages, and a GitHub runner build of everything runs into the 3-hour limit. Releases are built locally; the workflow only runs when started by hand | 11.0-5 built this way on an M4 under Rosetta |

## Upstreaming policy

Fixes that might help the wider Wine community start here, not as patches sent to WineHQ or CodeWeavers. A fix is proposed upstream only when all of these hold:

1. **Reproducible.** There is a minimal test case, or exact steps with a named application, that show the bug.
2. **Verified.** It has been tested on real hardware, with before/after results recorded here, and doesn't regress the CI smoke test.
3. **Understood.** The change is small, explained, and follows Wine's coding and submission guidelines (https://gitlab.winehq.org/wine/wine/-/wikis/Submitting-Patches).
4. **Reviewed.** A maintainer of this repository has reviewed and approved it.

No automated or bulk submissions. One well-tested patch beats many speculative ones.
